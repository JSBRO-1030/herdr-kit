# files-plus(파일+) — 미리보기 · 올리기 · 내려받기 파일 패널

herdr 앱 mod 입니다. 지금 눌린 터미널이 있는 폴더를 트리로 보여 주고, 아래 일을 합니다.

| 일 | 어떻게 | 어디서 되나 |
|---|---|---|
| 글자 파일 보기 | 기본 Files 와 같다(`readTextFile` · 1 MiB까지) | 어디서나 |
| 이미지 보기 | png · jpg · gif · webp · bmp · svg · ico · tiff · pnm. 원격이면 `hc exec` 로 받아 앱 폴더 `mods/files-plus/.cache/<sha256>/<이름>` 에 두고 `image()` 로 그린다. 16 MiB까지(앱 자산 상한) | 어디서나 |
| HEIC · HEIF · AVIF | 받은 뒤 `sips` 로 PNG 로 바꿔 그린다 | macOS 앱만 |
| PDF 전체 쪽 | 한 번에 한 쪽씩 본다. PageDown · PageUp, 툴바 위·아래 쐐기(첫·끝 쪽에서 흐림 · 1쪽 PDF 는 안 보임), 그림이 칸에 다 들어올 때의 휠 한 번 = 한 쪽. 캡션 `3 / 12쪽 · …`. 받은 뒤 쪽마다 macOS 기본 PDFKit 으로 PNG 를 만든다(`osascript` JXA 를 `/usr/bin/sandbox-exec` 안에서). 격리: 네트워크 거부 · 쓰기는 렌더러의 임시 폴더(+ `/dev/null`)만 · 읽기는 `${캐시}/<sha256>` 의 실제 경로 아래만(홈 폴더 읽기 거부) · fork 거부 · `/usr/bin/osascript` 외 실행 거부 · LaunchServices(`lsopen`) · Apple Events · 클립보드 mach 조회 거부. 홈 폴더는 실행 때 알아내며, 홈을 모르거나 `sandbox-exec` 가 없으면 첫 쪽만(«첫 쪽만 보임 (쪽 넘기기 불가: 격리 실행 없음)»). 쪽 그림은 `mods/files-plus/.cache/<sha256>/view/p<N>.png`(쪽 수는 `view/pages`)에 두어 다시 열면 재사용한다. 렌더는 창당 한 번에 한 쪽: 빨리 넘기면 마지막에 원한 쪽만 만들고, 다음 쪽 미리 만들기는 한가할 때만 한다. 빠른 보기 첫 쪽은 격리 렌더러 자체가 없을 때(`sandbox-exec` 없음 · 홈 모름)만 쓴다. 격리 렌더가 실패하면(잠김 · 5000쪽 초과 · 시간 초과 · 깨짐) 오류 문구가 뜬다 — 믿을 수 없는 PDF 를 더 약한 샌드박스에서 두 번째로 파싱하지 않는다. 다음 쪽 미리 만들기는 마지막 활동(쪽 넘김 · 렌더 끝) 뒤 400 ms 조용할 때 시작한다. 다시 열 때 이어 볼 쪽이 못 그려지면 같은 격리 렌더러로 1쪽을 한 번 더 시도하고(빠른 보기는 안 쓴다), 그림에 실패한 쪽은 «보던 쪽» 으로 기억하지 않는다. 크게 보기(F) · 가장자리 끌어 크기 바꾸기 · 모서리 두 번 클릭은 보던 쪽을 유지한다. 쪽 그리기가 실패해도 휠 · PageUp/PageDown 안내 · `N / M쪽` 캡션은 남는다 | macOS 앱만 |
| 문서 첫 쪽(docx · xlsx · pptx · key · pages · hwp 등) | 받은 뒤 빠른 보기(`qlmanage -t -s 1600`)로 첫 쪽 PNG 를 만들어 그린다. 200 MiB까지. 캡션 «첫 쪽만 보임 · 전체는 Mac에서 열기» | macOS 앱만 |
| 터미널에 나온 파일 | 패널 맨 위(머리줄 바로 아래) «터미널에 나온 파일 · N» 줄(접기 ▾/▸ · 새로고침 아이콘) — 터미널이 대상이면 늘 보이고, 파일이 0 이면 줄 없이 접힌 «터미널에 나온 파일 · 0» 머리와 새로고침 아이콘만 보인다. 어떤 에이전트(Claude Code · Codex · Gemini CLI …)나 일반 터미널에서도 된다. 지금 눌린 터미널의 보이는 글(`hc read` 마지막 300줄 · 5 초 안에 안 돌아오면 포기)에서 알려진 확장자(문서 · 이미지 · 코드 · 설정 파일)의 파일 이름 · 경로(에이전트 마크다운이 붙여 찍은 이름 · `file://` 링크 · 끝 `:줄번호` · `#L10-L20` · `--out=/tmp/x.pdf` 의 `=` 뒤 · `⏺` `⎿` `│` 같은 화면 장식 · `**굵게**`(앞 `**` 이상만 뗀다) · 끝 `?` 포함. URL 은 뺀다)를 찾아, 그 터미널이 있는 머신(이 컴퓨터 또는 원격)에 진짜 있는 파일만(POSIX `sh`) 최근 것부터 12개까지 보인다(8줄이 보이고 나머지는 스크롤 · 넘치면 문서 · 이미지를 먼저 남기고 코드 파일은 남는 자리에 — 단 아래 가벼운 훑기는 새 결과를 먼저 두므로, 찾기로만 나왔던 앞 문서 줄이 새로 직접 푼 줄에 밀려 빠질 수 있다). 에이전트가 줄바꿈으로 자른 긴 경로(2 줄 · 중간 줄이 토큰 하나면 3 줄)는 위 줄 끝과 아래 줄 머리를 이어 «추측» 으로 직접 풀기만 한다(찾기에는 넘기지 않는다). 이름 풀기는 두 단계: ① 직접(절대 · `~/` · 터미널 폴더 기준 상대) ② 못 푼 이름만 한 번 찾기 — 맨 이름은 이름이 같은 파일, 상대 경로는 경로 끝이 같은 파일(`*/src/a.json`). 줄을 누르면 미리보기(PDF 는 쪽 넘기기 포함). 터미널 · 폴더 · 상태가 바뀌면(800 ms 뒤) · 패널을 열 때 · 새로고침 아이콘으로 다시 훑고(전체 훑기), 에이전트가 working 인 동안은 10 초마다 가볍게 다시 본다(글이 그대로면 아무것도 안 하고, 바뀌었으면 직접 풀기만 · 찾기는 안 돈다 · 새 결과를 먼저 두고 남는 자리에 앞 목록을 잇는다). working 이 끝나면 다시 본다 — 터미널이 눌려 있으면 상태가 바뀐 것이므로 전체 훑기, 이 패널(그리드 칸)이 눌려 있으면 곧바로 한 번 가볍게(찾기 없음). 그 뒤 idle 에서 나온 새 출력(상태가 null 인 일반 셸 포함)은 상태 · 터미널 · 폴더가 바뀌거나 새로고침을 누르기 전에는 다시 훑지 않는다. 저절로 열거나 알리지 않는다. 없는 파일 · 폴더 · 글롭은 안 보인다(앞 `*` 하나 = 글롭이라 `ls *a.md` 의 `a.md` 도 안 나온다 · `**/a.md` · `*.ts` 도 마찬가지) | 어디서나(PDF 쪽 넘기기만 macOS) |
| md · html 페이지 | «페이지로» 단추 → `html-viewer` mod 를 옆 페인으로 연다(그 mod 가 깔려 있을 때만 보인다) | 어디서나 |
| 내려받기 | «내려받기» → 이 컴퓨터 `~/Downloads/<이름>`. 같은 이름이 있으면 `이름 (1).확장자` | 어디서나 |
| 이 컴퓨터에서 열기 | «Mac에서 열기» → 원격 파일이면 사본을 받아, 같은 머신 파일이면 원본을 `open`(리눅스는 `xdg-open`) | 어디서나 |
| 올리기 | Finder 에서 패널에 끌어다 놓는다. 폴더 줄 위에 놓으면 그 폴더로, 파일 줄 위면 그 파일의 폴더로, 빈 곳이면 맨 위 폴더로 간다. macOS 는 «올리기» 단추(파일·폴더 고르기 창 · `NSOpenPanel` · 여러 개 · 실패하면 `choose file`)도 있다. 폴더는 구조 그대로(빈 폴더 포함) 올린다: 같은 이름이면 새 폴더 `이름 (1)`(병합 안 함) · 링크 · 특수 파일 · `.DS_Store` · `._*` 는 건너뜀 · 상한: 한 번에 올리는 폴더 안 파일 합계 5000개(맨 위 낱개 파일은 합계에 안 듦) · 폴더마다 하위 폴더 2000개. 같은 이름이 있으면 `이름 (1).확장자` | 어디서나(단추만 macOS) |
| 새 폴더 | 트리 줄 오른쪽 클릭 → «새 폴더»(폴더 줄 = 그 폴더 안 · 파일 줄 = 그 파일의 폴더 안 · 빈 곳 = 맨 위 폴더) 또는 아래 «새 폴더» 아이콘. 이름 입력 창(기본 «새 폴더» · 있으면 «새 폴더 2»). 같은 이름이면 거절 | 어디서나 |
| 이름 바꾸기 | 줄 오른쪽 클릭 → «이름 바꾸기». 같은 폴더 안에서만. 파일은 확장자 앞까지 선택된다. 같은 이름이 있으면(파일 · 폴더 · 링크) 덮어쓰지 않고 거절 · 대소문자만 바꾸기 가능 | 어디서나 |
| 지우기 | 줄 오른쪽 클릭 → «지우기…». 휴지통 도구(macOS `/usr/bin/trash` · `gio` · `trash-put`)가 있으면 «휴지통으로 옮길까?» · 없으면 «영구히 지울까?»(빨간 경고 · «영구 삭제» 단추만 · Enter 로는 안 된다). 홈 폴더와 그 위 폴더는 지우지 않는다 | 어디서나 |

파일을 누르면 미리보기 창(열 때마다 가운데에서 뜬다 · Esc · ✕ 로 닫는다 · 머리줄을 끌어 옮긴다 · 옆을 눌러도 안 닫힌다 · →·스페이스 다음 · ← 이전 · 그림에서는 ↑↓ · Home/End 도 · 글자에서는 글 칸을 눌러야 ↑↓ 스크롤 · Esc 닫기 · 오른쪽 아이콘 줄 · ? 단축키)이 뜹니다. 전송은 전송 창(FTP 처럼 % · 아이콘: 모두 지우기 · 모두 취소 · Finder 열기 · 기록)에 보이고, 도는 중이거나 «대기» 중일 때 «취소»할 수 있습니다. 설계는 `docs/popups-design.md`. 여러 파일을 한꺼번에 놓아도 **한 파일씩 차례대로** 보냅니다. 내려받기와 올리기가 한 줄에 서므로, 큰 전송 뒤에 누른 «Mac에서 열기»는 앞 것이 끝나야 돕니다. 앱의 끌어 놓기 업로드도 한 파일씩 보냅니다. 폴더 올리기도 파일마다 한 파일씩 차례로 갑니다(내려받기는 파일만 — 폴더는 내려받지 않습니다).

## 옮기는 길과 지킨 것

- 다른 머신과는 이 컴퓨터의 `hc exec --on <머신>` 으로 바이트를 그대로 옮깁니다. html-viewer 가 PNG 를 받는 길과 같습니다.
- **`hc exec` 는 한 번에 출력 8 MiB · 입력 8 MB 까지다**(2026-11-13 이 상자 hc 0.1.19 실측). 넘치면 출력은 `[hc] output cut` 만 찍고 **rc 0 으로 잘린다.** 앱의 끌어 놓기 업로드(`hc put`)도 «at most 8 MB per put» 이다.
  - 그래서 4 MiB 조각(`dd bs=4194304 skip=i count=1`)으로 나눕니다.
  - 조각마다 받는 쪽 파일 크기를 기대값과 맞춥니다.
  - 끝에 sha256 을 맞춘 뒤에만 숨긴 `.이름.files-plus-*.part` 를 진짜 이름으로 옮깁니다.
  - 실패하거나 취소하면 조각 파일을 지웁니다. 앱이 죽어 못 지웠으면 다음 시작 때 죽은 삶의 스냅샷에 적힌 «도는 전송» 의 조각 경로(`part`·`partOn`) 하나씩만 지웁니다(조각 이름 꼴일 때만 · 폴더·glob 없음).
- 원격에도 `~/Downloads` 에도 덮어쓰지 않습니다.
- 경로는 모두 `sh -c` 의 위치 인자로만 넘깁니다(따옴표 · 공백 · `$` · 한글 이름 시험함).
- 이 컴퓨터(Mac)에서 도는 명령은 POSIX 만 씁니다: `dd`, `wc -c`, `sha256sum` 이 없으면 `shasum -a 256`.
- 올리기는 Mac 의 hc 가 `hc exec -i`(표준 입력 넘기기)를 알아야 합니다. 모르면 전송 칸에 «`hc update` 뒤 다시»가 뜹니다.
- 사본(`.cache/<sha256>`)은 마지막으로 쓴 지 하루가 지나면 mod 가 다시 뜰 때 지웁니다(폴더 mtime 기준 · 미리보기가 쓸 때마다 그 폴더를 `touch` 해 시각을 새로 한다).

## Mac 에 깔기

Mac 터미널에서. 저장소 `JSBRO-1030/herdr-kit`(이 폴더는 그 안의 `mods/`)은 공개라 로그인 없이 받을 수 있습니다. `gh` 가 없으면 `git clone https://github.com/JSBRO-1030/herdr-kit.git ~/herdr-option` 으로 받아도 됩니다.

```sh
gh repo clone JSBRO-1030/herdr-kit ~/herdr-option
mkdir -p ~/.config/herdr-app/mods
cp -R ~/herdr-option/mods/files-plus ~/.config/herdr-app/mods/
herdr-app check ~/.config/herdr-app/mods/files-plus     # «check passed» 가 나와야 한다
```

git 없이 원격 상자에서 바로 받을 때(`<머신>` = Mac 이 그 상자를 부르는 이름 · 상자 코어 `peers.json` 의 `calls_me`):

```sh
hc exec --on <머신> -- tar -C ~/herdr-option/mods -cf - files-plus | tar -C ~/.config/herdr-app/mods -xf -
```

여는 법(셋 중 하나):

```sh
herdr-app do pane.split '{"direction":"right","mod":"files-plus"}'   # 지금 탭 오른쪽 페인
herdr-app do tab.new '{"mod":"files-plus"}'                           # 새 탭
```

늘 쓰려면 `layouts/my-main.json` 의 `panel-body` 스택에 블록 하나를 더합니다(기본 `files` 옆):

```json
{ "id": "files-plus", "type": "block", "content": { "mod": "files-plus" } }
```

다시 깔 때는 `git -C ~/herdr-option pull` 뒤 `cp -R` 줄과 `check` 를 다시 돌립니다(파일을 덮어씁니다 · `.cache` 는 그대로). 지울 때는 `~/.config/herdr-app/mods/files-plus` 폴더를 지웁니다.

## 손 점검표 (Mac 에서 · `check` 가 못 보는 것)

`herdr-app check` 는 한 번 그릴 뿐이라 클릭 · 끌어 놓기 · 전송은 타지 않습니다.

0. `herdr-app --version` · `hc --version` 을 적어 둔다(만든 기준은 앱 0.1.15 · hc 0.1.19). 1번 앞에 `check` 가 떨어지면 앱부터 올린다.
1. 원격(`<머신>`) 공간의 터미널을 누르고 패널을 연다 → 그 터미널 폴더가 트리로 뜬다.
2. png · jpg 를 누른다 → 그림이 패널 폭에 맞게 뜬다. 아래 줄에 `가로×세로 · 크기`.
3. 20 MB 넘는 아무 파일 → «내려받기» → 전송 칸이 0→100% · `~/Downloads` 에 생긴다 · `shasum -a 256` 이 원격 `sha256sum` 과 같다.
4. 같은 파일을 한 번 더 «내려받기» → `이름 (1).확장자`.
5. Finder 에서 20 MB 넘는 파일을 폴더 줄 위에 끌어다 놓는다 → 그 폴더에 생긴다 · 해시가 같다. 전송 창이 저절로 펼쳐져 뜬다.
6. 큰 파일 전송 중 전송 창의 줄 «취소» 아이콘 → «취소»로 끝나고 받는 쪽에 `.part` 가 남지 않는다.
7. pdf · docx · xlsx 를 누른다 → 팝업에 첫 쪽 그림. 아이콘 줄 «Mac에서 열기» → 미리보기/기본 앱이 뜬다.
8. HEIC 사진을 누른다 → 그림이 뜬다.
9. 패널 아래 «올리기» 아이콘 → 파일 고르기 창이 앞에 뜬다(뒤에 숨거나 안 뜨면 알려 준다).
10. md 를 누른다 → 아이콘 줄 «페이지로» → html-viewer 페인이 옆에 뜨고 팝업이 닫힌다. html-viewer 가 없으면 그 아이콘이 안 보인다.
11. 패널(페인)을 눌러도 트리가 홈 폴더로 바뀌지 않는다.
12. Finder 에서 파일 20개를 한 번에 끌어다 놓는다 → 하나만 %로 돌고 나머지는 «대기» · 차례로 다 «끝» · 20개 모두 생긴다. «대기» 중인 것 하나를 «취소» → 그것만 «취소»로 끝나고 다음 것은 돈다.

39. 전송이 도는 중(대기 포함) 이름 바꾸기 · 지우기 → 알림 «전송이 끝난 뒤 다시» 로 거절. 새 폴더는 된다.
40. 원격(`<머신>`) 공간에서도 새 폴더 · 이름 바꾸기 · 지우기가 그 머신의 파일에 적용된다(경로 표시가 `머신:/…`).
41. 열려 있는 미리보기가 있는 폴더의 파일을 이름 바꾸기/지우기 → 미리보기 창이 닫힌다.
42. 이름 바꾸기 · 지우기 창을 연 채 10분 넘게 두었다가 확인 → 알림 «요청이 오래됐다 — 다시 할 것».

### 알려진 한계

- 렌더된 마크다운(호스트 `TextView`)은 키보드 스크롤이 없다 — 휠만.
- 이름 바꾸기 · 지우기: 이미 열려 있는 미리보기 창은 지운/바꾼 파일을 그대로 보일 수 있다 — 패널은 그 폴더 목록이거나 지운/바꾼 항목 안인 미리보기만 닫는다(목록 칸 · 정보 칸의 낡은 이름은 다음에 연 창부터 바로잡힌다).
- 파일 작업의 확인과 `mv`/`mkdir`/삭제 사이에는 TOCTOU 가 있다 — 이름 바꾸기는 사후 확인(inode · 목록의 정확한 이름)으로 잡고, 새 폴더는 `mkdir` 자신이 있는 이름에 실패한다. 전송이 새로 시작되는 순간과 겹친 이름 바꾸기 · 지우기는 막지 못한다(시작 전 검사만).
- 영구 삭제(휴지통 도구가 없는 머신)는 마운트 지점을 넘지 않는다 — Linux 는 `rm` 종류와 무관하게 `/proc/self/mountinfo` 로 «안에 마운트가 있으면» 먼저 거절하고(종료 코드 12 · 못 읽거나 빈 정보면 6) GNU coreutils 면 OS 무관(macOS + brew coreutils 포함) `--one-file-system` 을 덧붙인다(Linux 의 uutils · busybox 는 플래그 없이) · GNU 가 아닌 macOS 는 `-x`(플래그를 모르는 `rm` 이면 오류로 끝나고 다시 시도하지 않는다). 확인 창이 본 대상과 지울 대상은 id(`종류:dev:ino`)로 묶여 있어, 그 사이 바뀌었으면 «확인한 뒤 대상이 바뀌었다 · 다시 열어 확인하라»(종료 코드 10) · 폴더를 지우다 일부만 지워졌으면 종료 코드 11 로 «일부는 이미 지워졌을 수 있다(되돌릴 수 없다)» 를 알린다. 메뉴 · 지우기 창은 누르고 있는 Enter(`is_held`)를 무시하고, 이름 입력 창은 열린 뒤 350 ms 안의 Enter 만 무시한다(`Input` submit 에는 `is_held` 가 없다 — 그 뒤에 Enter 를 계속 누르고 있으면 제출된다 · 되돌릴 수 있다). 단추 클릭은 그대로.
- macOS 의 영구 삭제: 같은 장치로 붙인 마운트(bind 류 · `-x` 가 st_dev 비교라 못 잡는다)는 넘어간다 — Linux 는 mountinfo 검사로 거절한다.
- 휴지통이 실패하면(권한 · 가득 참 · 다른 볼륨) **영구 삭제로 넘어가지 않고** 오류만 알린다. macOS 의 `/usr/bin/trash` 는 `uname` 이 Darwin 일 때만 쓴다(리눅스 trash-cli 의 `trash` 와 구별).
- 파일 다루기: HFS+ 볼륨에서 한글 새 이름으로 바꾸면 디스크엔 반영됐는데 «결과를 확인하지 못했다» 로 뜰 수 있다(이름 비교가 바이트 단위 — 정규화가 다름).
- 파일 다루기: 시스템 최상위 폴더(`/etc` · `/usr` …)를 막는 차단 목록은 없다 — 홈 폴더와 그 위 폴더만 막는다(`HOME` 이 비어 있으면 그 보호도 꺼진다).
- 파일 다루기: 티켓이 작업 종류(새 폴더 · 이름 바꾸기 · 지우기)에 묶여 있지 않다 — 한 티켓으로 다른 종류의 요청도 만들 수 있다(1회용 · 10분).
- 파일 다루기: 작업 중 다른 공간으로 옮기면 그 공간의 «펼친 폴더 기억» 이 지운/바꾼 폴더를 그대로 둘 수 있다(기존 문제 — 돌아오면 읽기 오류가 난다).
- 파일 다루기: 줄바꿈이 든 이름은 메뉴는 열리지만 요청이 «거절» 된다.
- 파일 다루기: 이름 바꾸기 · 지우기를 실행하는 중에 새 전송을 시작할 수 있다(시작 전 검사만).
- 파일 다루기: 대소문자만 다른 이름으로 바꾸는 두 단계 이름 바꾸기 도중 시간 초과가 나면 항목이 `.files-plus-rename-<번호>` 이름으로 남을 수 있다.
- Herdr 에는 터미널 링크 클릭을 받는 mod 훅이 없다. 원격 파일 링크를 터미널에서 ⌘+클릭해도 아무 일이 없다(Herdr 는 이 컴퓨터 경로만 연다). 대신 패널의 «터미널에 나온 파일» 줄을 쓴다.
- PDF 쪽 넘기기는 macOS 앱만(`osascript` · `/usr/bin/sandbox-exec` 필요). 리눅스 앱은 PDF 를 아예 미리보지 않는다(문서 미리보기가 Mac 전용 — «문서·HEIC 미리보기는 Mac 앱에서만 된다» 안내만 · 열기 · 내려받기는 된다). 잠긴(암호) PDF 는 쪽 렌더가 실패해 오류 안내가 뜬다(빠른 보기로 다시 열지 않는다).
- `sandbox-exec` 는 있는데 프로필 적용이 실패하면(OS 가 거부 등) PDF 는 첫 쪽 대신 오류 안내가 뜬다.
- «터미널 폴더가 홈의 상위면 찾지 않는다» 는 실제 경로(`pwd -P`)끼리만 비교한다 — 링크된 홈을 거치는 논리적 상위 폴더에서는 찾는다.
- 트랙패드로 쓸면 한 번에 여러 쪽이 넘어갈 수 있다(스크롤 40 px 마다 한 쪽). 렌더는 한 번에 한 쪽이라 마지막에 원한 쪽만 만든다.
- «터미널에 나온 파일» 줄은 터미널의 **보이는 글**(`hc read`)만 본다. OSC 8 로 숨은 링크 주소는 못 본다. 줄바꿈으로 잘린 이름은 위 줄 끝 + 아래 줄 머리를 이어 보지만, 단어 경계에서 접힌 것과 토큰 중간에서 잘린 것은 글자만으로는 구별이 안 되므로 이은 이름은 추측이다 — 직접 풀기(절대 · `~/` · 터미널 폴더 기준)로만 확인하고 찾기에는 넘기지 않는다(그래서 깊은 하위 폴더의 잘린 이름은 놓칠 수 있다). working 중 10 초 가벼운 훑기에는 찾기가 없고, 새 결과를 먼저 두고 남는 자리(12 개까지)에 앞 목록의 줄을 잇는다 — 새 결과가 12 개를 다 채우면 앞 줄이 빠지고, 그렇지 않으면 전체 훑기 전까지 남는다(그 사이 지워진 파일이 남아 있을 수 있다). 직접 못 푼 이름의 찾기는 한 번만(이름 10개까지 · 전체 24개 · 이름마다 3개 · `-xdev` · `.git` · `node_modules` 건너뜀): 깊이는 터미널 폴더에서 센다(폴더 바로 안의 파일 = 깊이 1). 맨 이름은 깊이 3 까지, 조각 N 개짜리 상대 경로는 깊이 N+2 까지(최대 6). 후보마다 한도가 따로라 긴 경로가 맨 이름의 깊이를 늘리지 않는다. 조각 6개 경로는 자기 깊이(6)에서만 맞고, 7개 이상은 찾기로 못 찾는다. 경로는 맨 이름으로 되돌려 찾지 않는다. 터미널 폴더가 `/` · 홈 폴더 · 홈 폴더의 상위 폴더(예 `/Users`)면 찾지 않고, 찾기가 실패하거나 10 초를 넘기면 직접 푼 결과만 쓴다.
- «터미널에 나온 파일» 줄: 식별자 모양 이름(`node.js` · `res.json` · `this.cmd` 등 코드 글자)도 후보가 되어 찾기 10자리를 먹을 수 있다.
- «터미널에 나온 파일» 줄: 줄바꿈으로 잘린 조각(`quarterly-re` + `port.pdf` 의 `port.pdf`)과 확장자 중간에서 잘린 이름(`Button.ts` + 다음 줄 `x`)은 직접 후보로 남아 찾기에 간다 — 같은 끝 이름의 다른 파일(`…/Button.ts`)이 뜰 수 있다.
- «터미널에 나온 파일» 줄: 줄 잇기 추측도 후보 상한(40 · 코드 20)에 센다.
- «터미널에 나온 파일» 줄: 파일이 생기기 전에 이름이 먼저 찍히고 그 뒤 화면 글이 그대로면, 가벼운 훑기는 글이 같다고 보고 다시 풀지 않는다 — 상태가 바뀌거나 새로고침을 눌러야 나온다.
- «터미널에 나온 파일» 줄: 마크다운 기울임 `*name.ext*` 는 줄이 안 생긴다 — 앞 `*` 하나는 글롭으로 보기 때문이다(`ls *a.md`).
- «터미널에 나온 파일» 줄: `git diff` 의 `a/` · `b/` 머리는 떼지 않는다(그래서 diff 머리줄의 파일은 직접 못 푼다).
- «터미널에 나온 파일» 줄: 상태가 바뀌면(에이전트가 끝나거나 권한을 물을 때) 전체 훑기 결과로 바꾼다 — 300줄 밖으로 밀려난 앞 줄은 그때 사라진다. 이 패널이 그리드 칸으로 눌려 있으면 그 대신 working 이 끝날 때 가벼운 훑기 한 번뿐이다 — 찾기가 없어 하위 폴더의 맨 이름(`deep.pdf`)은 안 나오고 앞 줄도 남는다(새로고침을 누르면 전체 훑기 — 터미널을 다시 눌러도 그때 상태 · 폴더가 앞과 같으면 다시 훑지 않는다).
- «터미널에 나온 파일» 줄: 그리드 칸으로 눌려 있을 때 working 끝의 가벼운 훑기는 기다리지 않고 곧바로 돈다 — 상태가 바뀐 직후(~0.3 초 안)에 찍힌 마지막 줄은 놓칠 수 있고, 그 한 번의 `hc read` · 풀기가 실패해도 다시 하지 않는다(새로고침으로 다시 찾는다). 상태가 working 과 다른 상태 사이를 빠르게 오가면 바뀔 때마다 한 번씩(한 번에 하나) 가볍게 훑는다.
- «터미널에 나온 파일» 줄: 그리드 칸으로 눌려 있는 동안 상대 이름은 마지막으로 터미널을 눌렀을 때의 폴더 기준으로 푼다 — 그 뒤 터미널 폴더가 바뀌었으면 옛 폴더의 같은 이름 파일이 뜰 수 있다(줄은 미리보기 · 열기 · 내려받기만 한다). 터미널을 다시 누르면 맞춰진다.
- «터미널에 나온 파일» 줄: 접어 둔 동안에도 working 중 10 초 훑기는 돈다 · 시간 초과된 `hc` 호출은 취소하지 않는다(결과만 버린다).
- «터미널에 나온 파일» 줄: 멎음 감시 — 훑기가 30 초 넘게 안 끝나면(호스트가 끊은 task 는 약속이 영영 안 끝난다) 버리고 새로 시작한다. 가벼운 훑기가 멎었으면 가볍게(원격 `find` 없이) 다시 시작한다 — 단 전체 훑기 요청이 줄 서 있었거나 새로고침 아이콘 · 터미널 · 폴더 바뀜 직후면 전체로. 연속으로 버리면 감시의 기다림이 30 초 → 60 → 120 → 240 → 480 초(상한)로 늘고, 끝난 훑기가 하나라도 있으면 30 초로 돌아간다. 새로고침 아이콘을 누르거나 터미널 · 폴더가 바뀌어 전체 훑기가 줄 서면, 늘어난 기다림과 상관없이 도는 훑기가 30 초가 되는 때 버리고 새로 시작한다 — 상태(working ↔ idle)만 바뀐 것은 늘어난 기다림을 따른다. 새로고침 아이콘: 도는 훑기가 어리면(30 초 미만) 끝난 뒤 한 번만 다시 훑도록 줄 세우고, 30 초 넘게 멎었으면 바로 버리고 새로 시작한다(연타해도 원격 `find` 가 쌓이지 않는다). 버린 훑기의 늦은 결과는 목록 · 상태를 건드리지 않는다.
- «터미널에 나온 파일» 줄: 버린 훑기의 원격 `exec`(풀기 · 찾기)는 끊을 수 없다 — 제 시간 초과(10 초)까지 그 머신에서 계속 돈다.
- «터미널에 나온 파일» 줄: 30 초 넘게 멎은 훑기 도중 터미널 · 폴더를 바꾸면 감시가 곧바로 새 대상의 전체 훑기를 시작하고, 바꿈이 줄 세운 전체 훑기가 그 뒤에 한 번 더 돈다 — 그 머신이 멀쩡하면 원격 `find` 가 한 번 더 나간다(멎었으면 버릴 때 줄 선 요청이 지워져 쌓이지 않는다).
- «터미널에 나온 파일» 줄: 진단 기록 — 마지막 훑기 결과가 `~/.config/herdr-app/shared.json` 의 `files-plus.tf/<owner>` 에 남는다(`{at, phase, kind, cands, found, shown, code?, err?, search?, abandons?, lastAbandon?: {stage, kind, age}}` · 이름 · 폴더 · 터미널 글은 안 넣는다). `phase`: `no-cwd` · `read-failed` · `no-text` · `same-text` · `resolve-failed` · `parse-failed` · `ok`(찾기만 실패하면 `search: "failed"`) · `abandoned` · `tick-error`. `shown` = 줄이 실제로 보여 주는 수. `err` 는 `timeout` · `failed` · `parse` · 글자만으로 된 오류 이름 중 하나뿐이다(메시지 글은 남기지 않는다). `lastAbandon` = 마지막으로 버린 훑기가 멎은 단계(`spawn` · `read` · `scan` · `resolve` · `search` · `merge`) · 종류 · 나이(초). 쓰기: 분류가 바뀌거나 개수(`cands` · `found` · `shown`) 중 하나가 0 이 되거나 0 에서 벗어나면 바로, 그 밖의 개수만 바뀌면 15 초에 한 번까지 · ok 기록 뒤의 same-text 가벼운 훑기는 쓰지 않는다(그래서 기록의 0 아닌 개수는 다음 쓰기 전까지 띠보다 뒤처질 수 있다). «· 0» 이 오래 가면 이 값부터 본다. 기록의 한계: 멎은 나이는 벽시계(`Date.now`)로 재서 잠자기에서 깨면 가짜 버림이 남을 수 있다 · hc 읽기의 `err: "timeout"` 은 걸린 시간으로 추정하고 exec 의 시간 초과는 오류 글로 가린다 · `search: "failed"` 는 합치기 오류일 수도 있다. 예전에 «· 0» 이 몇 시간 이어진 원인은 확인하지 못했다 — 위 감시는 «훑기가 안 끝나 영영 막힘» 가설에 대한 방어이고, 기록은 재발 시 원인을 가리려는 것이다.
- «터미널에 나온 파일» 줄: 패널을 닫거나 다시 불러오면 진단 기록이 지워진다 → «· 0» 이 다시 나오면 닫기 · 다시 불러오기 전에 `shared.json` 의 `files-plus.tf/<owner>` 를 보거나(알리거나) 해야 한다.
- «터미널에 나온 파일» 줄: 기록의 `at` 은 심장 박동이 아니다 — 틱이 죽었거나 타이머가 `tfPending` 에 걸려 멈춘 것은 기록에서 보이지 않는다(확인 안 된 후보).
- `=` 는 토큰 경계라 `--out=/tmp/x.pdf` 에서 `/tmp/x.pdf` 를 얻지만, 이름 안에 `=` 가 든 진짜 파일은 `=` 앞부분을 잃는다.
- 이 컴퓨터 터미널 안에서 `ssh` 로 들어간 서버의 파일 이름은 그 서버가 아니라 Mac 에서 푼다(머신은 터미널이 속한 곳 기준).
- `**굵게**` 가 굵어 보이지 않을 수 있다(호스트 렌더러 · 글꼴 — 확인 필요).
- 핀치 · 회전 입력 API 없음.
- 열기 검사와 `open` 사이 TOCTOU.
- ⌘ 를 먼저 떼고 방향키를 250 ms 넘게 누르면 글 칸을 누른 뒤에도 파일이 넘어갈 수 있다.
- `layout.hide` 로 패널을 숨겨도(mod 는 계속 돈다) 미리보기 창은 남는다 — 숨김을 알 API 가 없다(`layout()` 은 형태가 문서에 없고 `resizable_panel.visible` 은 그리기 쪽 입력이다). Esc · ✕.
- 미리보기 변환(`qlmanage` · `sips`)은 취소할 수 없다 — `exec` 에 취소 수단(Task · AbortSignal · kill)이 없다. 결과만 버린다.
- 크래시로 남은 다른 owner 의 흔적은 주인 등록부(`files-plus.owners` · ≤ 20 · 15 s 마다 `at` · 60 s 넘게 갱신 없음 + 이 프로세스에 없음 = 죽음)로 패널 초기화 때와 60 s 마다 치운다. 패널이 초기화돼야 돈다 — 앱을 다시 켠 뒤 패널이 자동으로 안 열리면 열 때까지 정리는 기다린다.
- 그림은 크기를 확실히 읽을 때만 그린다(`pictureCheck` = `imageSize ?? declaredSize`). 모르면 «크기를 알 수 없는 그림이다» 로 거절(열기 · 내려받기는 됨). SVG 는 DOCTYPE 내부 부분집합 · em/ex · viewBox 없이 크기 없음/% · 접두 붙은 크기 속성 · 루트가 svg 아님 · 루트 태그 16 KB 초과 · 풀리지 않은 `&` · svgz, ICO · TIFF · PNM 은 머리글이 이상한 파일(항목 512 초과 · 중복 태그 · 숫자에 붙은 주석 등)이 걸린다.
- 호스트 JS(QuickJS)에는 `TextDecoder` · `TextEncoder` · `structuredClone` · `Intl` · `AbortController` 가 없다(node 시험은 통과해도 앱에서 던진다) — `kinds.js` 는 latin1 변환(`String.fromCharCode` 조각)을 쓴다. 새 전역을 쓰기 전에 샌드박스 `herdr-app check` 로 확인한다.

## 터미널에서 더블클릭으로 열기

터미널에서 파일 이름(경로)을 마우스로 더블클릭하면 그 파일이 미리보기로 열립니다(`dcTick`).

- macOS 전용 · 마우스 선택만. `copy_on_select` 가 켜져 있어야 합니다(기본값). 선택한 글이 클립보드로 복사돼야 이름을 알 수 있습니다.
- 마우스를 받는 프로그램(vim · tmux 등) 안에서는 Shift+더블클릭.
- `:42` 같은 줄 번호는 낱말 선택에서 빠지고 이름만으로 엽니다(`note.md:42` → `note.md`). 공백 · `(` 로 잘린 이름은 잘린 뒤쪽 낱말만 보므로, 그 이름의 파일이 지금 폴더에 있으면 그 파일이 열립니다(`Q3 report.pdf` 의 `report.pdf`). 공백이 든 이름은 «터미널에 나온 파일» 줄을 씁니다.
- 끌어서 고른 선택도 같은 길로 열립니다. mod 는 끌기와 더블클릭을 구별하지 못합니다.
- 같은 낱말을 다시 더블클릭하면 보통 다시 엽니다(마우스를 누를 때 잠깐 풀리는 선택을 300 ms 틱이 잡아야 합니다 · 못 잡으면 다른 곳을 한 번 누른 뒤). 그대로 둔 선택은 다시 열지 않습니다. 터미널에서 연 파일은 선택이 풀릴 때까지 그 터미널에서 다시 열지 않습니다(패널을 숨겼다 보이거나 크기를 바꿔 선택이 밀려도 같습니다).
- 터미널의 마지막 300 줄에 나온 이름만 엽니다.
- 한 경로에 붙은 끝의 `.` · `#L12` · 상대 경로의 `**굵게**` 같은 장식은 떼고 엽니다. 공백이 든 선택은 아무것도 열지 않습니다. allowlist: 앞의 `*` `「` `『` `«` `【` `《` `〈`, 뒤의 `#L12` · `#L12C3` · `*?!。、.,;:` `」』»】》〉`, 이름 바로 뒤에 붙은 한글/일본어 조사(`docs/plan.md를` → `docs/plan.md`)는 떼고 엽니다. 이름이 라틴 글자·숫자로 이어지면(`data.jsonl` · `a.md.bak`) 아무것도 열지 않습니다. 보이지 않는 한글 채움 문자(U+115F · U+1160 · U+3164 · U+FFA0)는 이름 뒤 꼬리(조사 시작 · 이어짐 자리)에서 받지 않습니다.
- 더 긴 이름 확인: 이름 바로 뒤에 한글·일본어·한자 꼬리가 붙은 선택(`보고서.pdf사본` · `data.csvの备份`)은 글자만으로는 조사(`plan.md를`)와 구별되지 않습니다. 그래서 터미널 글에 나온 그 꼬리를 이름에 붙인 것(앞에서 8 글자까지 하나씩 · 선택한 꼬리는 첫 장식(`.` · `、` · `」` 등) 앞까지의 글자 줄만 확인합니다 — `보고서.pdf사본.백업` 을 고르면 `보고서.pdf사본` 까지만 봅니다. 꼬리는 통째로 보내므로 8 글자 한도는 줄바꿈 탐침의 같은 줄 글에만 적용됩니다)을 같은 폴더에서 같이 찾아, 그 파일이 하나라도 있으면 아무것도 열지 않습니다(없으면 짧은 이름이 열립니다). 더 긴 파일만 있고 짧은 이름이 없을 때도 열지 않습니다.
- 줄바꿈 확인: 이름이 줄 끝에서 끝나고 다음 줄 머리가 이어지는 글처럼 보이면(`a.md` / `.bak` → `a.md.bak`) 이어 붙인 이름의 파일이 있을 때 아무것도 열지 않습니다(Gemini 상자 · Claude 들여쓰기 줄바꿈도 같습니다). 줄 끝이 닫는 장식(`)` · `'` · `」` …)이면 이름이 줄 끝에서 끊긴 게 아니므로 줄바꿈으로 보지 않습니다(`built (x.js)` / `.map …` 은 `x.js` 가 열립니다). 파일 목록(`ls -1`)처럼 줄마다 따로 있는 이름은 영향이 없습니다.
- 확인하지 못하는 경우: 다음 줄 하나만 봅니다(둘 넘게 이어진 줄바꿈은 안 봅니다). 거울 경우 — 이름이 줄 머리에 있고 앞 줄이 `docs/` 로 끝난 경우 — 는 보지 않습니다. 낱말의 일부만 끌어 고르면 그 부분이 열립니다(`보고서.pdf사본` 에서 `보고서.pdf` 만 고르면 `보고서.pdf` 가 열립니다).
- 남은 한계 / 확인하지 못하는 경우:
  - 한 줄 선택에서 이름 뒤 꼬리가 터미널 글에 그대로 없으면(오래 위로 스크롤해 읽은 300 줄 밖 · 클립보드는 NFC 인데 터미널은 NFD 등) 더 긴 이름을 확인할 수 없어 아무것도 열지 않습니다.
  - NFD 한글 꼬리는 글자(음절)가 아니라 코드 포인트 단위로 앞 8 걸음을 세어 2–4 음절만 보이고, 음절이 덜 만들어진 조각도 확인 이름으로 보낼 수 있습니다.
  - 줄바꿈으로 갈라진 꼬리는 다음 줄 머리 모양(`.bak` 류 점 확장자 · 한글/가나 글자로 시작해 한글/가나/한자로 이어지는 8 자까지 — 가나 범위라 `・` · `ー` 도 시작 글자로 받습니다)만 확인합니다. 짧은 소문자·숫자 토큰(`on` · `l` · 4 자리 코드)은 확인 명령(`sh -c` 인자)으로 가지 않습니다(영어 문장 줄바꿈 `config.js` / `on` 이 `config.json` 을 오탐하지 않게). 머리 토큰 뒤가 줄 끝 · 공백 · 상자선이 아니면 보지 않습니다. 같은 줄에서 이름 뒤 글은 없음이거나 글자 8 자 이하 글자열일 때만 붙입니다(`.` · `#L41` · 그 밖이면 그 줄은 건너뜁니다). 앞 글자씩 늘려 보는 단계는 없습니다.
  - 이름이 확장자 «안» 에서 갈린 경우(`data.json` / `l` · `a.md.` / `bak`)와 이름 «안» 에서 두 줄로 갈린 경우(`docs/pl` / `an.md사본`)는 확인하지 않습니다 — 더 짧은 이름이 열릴 수 있습니다.
  - 더 긴 이름 탐침은 마지막 조각이 UTF-16 글자 255 단위를 넘으면 빠집니다(바이트가 아니라 글자 단위 — 한글 이름 86 자 이상도 확인됨). 이 단위를 넘는 이름은 이 볼륨들에서 만들 수 없다고 가정합니다(파일 시스템이 더 긴 이름을 허용하면 그 탐침만 빠져 짧은 이름이 열릴 수 있습니다).
  - 두 줄(줄바꿈) 선택에서 글자 꼬리가 다음 줄로 이어지면 다음 줄 머리 모양으로만 확인합니다. 더 긴 이름의 꼬리가 8 자를 넘거나 허용 모양이 아니면 짧은 파일이 열릴 수 있습니다(이번 변경 전과 같습니다).
  - 두 줄 선택에서 더 긴 이름이 첫 줄에서 끝나면(`보고서.pdf사본` / `을`) `이름+꼬리+다음 줄 머리` 만 확인하고 `이름+꼬리` 는 확인하지 않아, 짧은 파일이 열릴 수 있습니다(이번 변경 전과 같습니다).
  - 느린 네트워크 파일 시스템에서는 확인이 4 초 열기 한도를 넘길 수 있습니다(확인은 같은 호출에서 한꺼번에 합니다).
  - 읽을 수 없거나 일반 파일이 아닌 더 긴 이름은 거부 근거가 되지 않습니다.
  - 마지막 300 줄 어딘가에 `a.md` 다음 줄 `.bak` 같은 오래된 쌍이 있으면 `ls -1` 에서 고른 `a.md` 가 거부될 수 있습니다. 줄 끝 일치는 최신 4 개만 확인합니다.
- 굵은 글씨 절대 경로를 `**/abs/path**` 처럼 별표째 쓴 것은 알아보지 못합니다(앞의 `**/` 를 glob 으로 봅니다 · «터미널에 나온 파일» 줄도 같습니다). Claude Code 는 굵은 글씨를 별표 없이 보여 주므로 드뭅니다.
- 창이 다른 터미널을 보여 주는 중(`terminal.show`)에는 아무것도 열지 않습니다.
- 포커스가 없는 칸의 낱말도 바로 더블클릭하면 열립니다. 다만 그 칸에 이미 선택돼 있는 바로 그 낱말을 다시 더블클릭하면 가끔(VM 10번에 2번) 놓칩니다 — 그 칸을 한 번 누른 뒤 더블클릭합니다.
- 미리보기가 뜨면 키보드를 가져갑니다. 그 직후의 다음 더블클릭은 첫 누름이 미리보기 창에 먹혀 열리지 않을 수 있습니다 — 터미널을 한 번 누른 뒤 더블클릭합니다.
- 낡은 클립보드 위험: `copy_on_select` 가 꺼졌거나 복사가 늦으면, 칸 수가 같고 터미널에도 찍힌 클립보드의 경로가 대신 열릴 수 있습니다. 터미널 안의 프로그램이 OSC 52 로 클립보드를 다시 쓸 수도 있습니다(Herdr `clipboard_write` 기본 켜짐).
- files-plus 패널 사본이 여럿 살아 있으면(숨긴 열 · 다른 탭) 사본마다 따로 반응해 미리보기가 여럿 뜰 수 있습니다.
- 찾는 데 4 초 넘게 걸리면(느린 원격) 열지 않습니다(늦게 뜬 미리보기가 키보드를 가져가지 않게).
- 원격 머신으로 등록된 터미널이면 그 머신에서 찾아 엽니다(VM 에서 다른 계정으로 ssh 한 머신으로 확인 · 실제 망을 건너는 회선은 아직). ssh 를 돌리는 로컬 터미널은 Mac 에서 찾습니다.
- 끌어 고른 선택이 원격의 그림 · 문서 이름이면 내려받아(최대 200 MB) 내용을 보여 줍니다.
- 클립보드는 읽지만, 터미널 글에서 찾은 경로 후보 중 하나를 «고르는 데만» 씁니다(선택 칸 수와 글 폭이 맞고, 터미널 글에 그대로 있어야 함). 저장 · 기록 · 전송하지 않고, 클립보드에서만 온 글은 어디에도 실행되지 않습니다.

## 안 해 본 것

- `--on` 으로 진짜 다른 머신을 탄 전송(같은 스크립트를 `--on` 없이만 쟀다).
- Mac 에서만 도는 길: `qlmanage` 첫 쪽, `sips` 변환, `osascript` 파일 고르기, `open`. 그리고 Finder 끌어 놓기.
- 원격 머신의 `sha256sum` / `shasum` 이 둘 다 없는 경우(그때는 «sha256 도구가 없다»로 멈춘다).
- 많은 파일을 한꺼번에 놓았을 때의 한 줄 전송(시험은 node 에서 넷 · 화면은 고정 상태만 봤다).
