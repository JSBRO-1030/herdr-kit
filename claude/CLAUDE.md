## herdr 팀워크 (herdr-option)

- 여러 단계 일을 받으면 먼저 «혼자 · 나눔 · 같이»를 판정해 한 줄로 말한다(«판정: …»).
  - 혼자: 몇 분이면 끝나거나, 한 갈래를 차례로 하거나, 사용자와 대화 중인 일.
  - 나눔: 서로 기다리지 않는 긴 갈래가 둘 이상이거나 오래 도는 실행이 있다 → 갈래마다 도우미 하나.
  - 같이: 되돌리기 어렵거나 남에게 갈 산출물 → 다른 모델이 검수한다(저자 ≠ 검증자).
- 도우미는 `herdr-team` 스킬(`~/.claude/skills/herdr-team/team.sh`)로 Herdr 앱의 옆 페인·탭(hc 터미널)에 띄운다. 띄우기 전에 `team.sh doctor` 로 이 상자에 깔린 CLI 를 보고, 그중에서 일을 해낼 수 있는 가장 싼 것을 고른다.
- 사용자가 «옆에» «탭» «옆 팬» «클러드 켜서»라고 하면 말한 그대로 한다 — «필요 없다»고 되받거나 보이지 않는 서브에이전트로 바꾸지 않는다.
- 10분 안에 끝나는 짧은 일은 껍데기 에이전트(`agy-worker` · `grok-worker` · `opencode-worker-free` 중 깔린 것)에 맡긴다. 시한에 걸리면 스크립트가 탭으로 넘긴다.
- 도우미가 낸 숫자·주장은 원본과 대조한 뒤 보고한다. 결과를 받으면 내가 연 페인은 닫는다.
- 내가 도우미 안이면(환경 변수 `HERDR_TEAM_HELPER=1`) 페인을 만들지 않고 자기 CLI 의 하위 에이전트로 나눈다.
- herdr 는 `hc`(herdr-core)로만 다룬다. 옛 `herdr pane/agent/tab` 명령은 쓰지 않는다. 매뉴얼은 `hc --skill`.
- 사용자에게 문서(HTML·Markdown)를 보일 때는 `herdr-open` 스킬로 Herdr 앱 화면에 연다.
- 세션이 길어지면(3시간 · 문맥 50% 즈음) 인계를 먼저 쓰고 `session-rotate` 스킬로 교대한다. 교대를 띄운 뒤에는 도구를 더 부르지 않는다.

## 작업 기본 규칙

1. 고치기 전에 생각한다 — 접근과 장단점을 먼저 적는다. 짐작으로 고치지 않고, 낡은 사용법을 피하려고 최신 문서를 먼저 찾는다.
2. 단순하게 — 지금 필요한 것만 짓는다. 쓸 일이 확실해질 때 구조를 만든다.
3. 맡은 곳만 고친다 — 곁의 코드를 덩달아 정리하지 않는다.
4. 끝의 기준을 먼저 정하고 시험으로 확인한다. 시험이 초록이어야 끝이다.
5. 모호하면 묻는다. 물을 때는 잰 사실과 선택지(장단점)를 함께 준다.
6. 실패한 명령은 정확한 오류를 잡고 원인을 확인한 뒤 다시 돌린다 — 확인 안 된 원인으로 반복하지 않는다.
7. 숫자·상태 보고는 구조화된 필드나 정확한 일치로 센다. 느슨한 grep 필터로 세지 않는다.
8. 긴 산출물은 파일로 남기고, 답에는 요약과 경로만 적는다.
9. 작게 돌아가는 판에서 한 층씩 더한다. 층마다 아직 돌아가는지 확인한다.
